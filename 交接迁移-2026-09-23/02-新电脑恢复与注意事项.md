# 新电脑恢复与注意事项

## 一、先搬文件

1. 将 `乐颜秀-私有迁移包-2026-09-23.zip` 和 `迁移包.sha256` 通过可信渠道复制到新机。ZIP 未加密，含 `.env`、本地数据和历史证据，按私有备份保管。
2. 用 `Get-FileHash -Algorithm SHA256 <ZIP路径>` 核对校验文件。解压到专用目录，例如 `D:\Projects\leyanxiu-workspace`。首次解压不要覆盖另一个已有工作树。
3. 确认隐藏 `.git`、`server/.env`、`server/.env.stage.secrets`、源码/素材/部署文档均在。ZIP 包内附逐文件哈希清单，可运行 `python 交接迁移-2026-09-23/verify-migration.py` 校验（该脚本只读）。
4. 打开根目录让 Codex 读取 AGENTS.md 与交接文件。无需把旧对话是否可见作为接手前提。
5. 旧机与新机之间只保留一个主动开发者；本迁移包是时间点快照，打包后的改动须另同步。

### 本地启动

默认 `server/env.js` 自动读真实 `server/.env`，其中可能有云端写入配置。**新机首次本地调试应使用独立测试环境文件和全新数据目录，不能直接拿真实配置启动。**

1. 从 `.env.example` 新建 `.env.local-handoff`，保留原 `.env` 不覆盖。
2. 测试配置：`DEPLOY_ENV=development`、`PROVIDER=mock`、`AUTH_MODE=anonymous`、`PAYMENT_MODE=closed_test`、`CLOSED_TEST_MODE=true`、`TASKS_BACKEND=file`、`OBJECT_STORAGE_BACKEND=file`、`PORT=8787`，其他配置按 env 示例和实际 readiness 补齐。不要复制云端 OSS 快照配置进隔离测试文件。
3. `COMPLIANCE_STORE_FILE`、`TASKS_FILE`、`PRIVATE_OBJECT_DIR`、`OBJECT_INDEX_FILE`、后台存储目录指向独立空目录；避免碰旧数据。若选择 SQLite，同样使用新的测试数据库路径。
4. 在 server 终端设置 `$env:DOTENV_CONFIG_PATH` 为该测试文件绝对路径，再 `npm run dev`。检查终端实际监听端口。
5. 在 app 的另一终端运行 `npm run dev -- --host 127.0.0.1`，前端默认3000、代理默认8787。需要换后端时设置 `VITE_DEV_API_PROXY`；不要让前后端抢同一个3000端口。
6. `/health` 只说明进程存活，`/api/readiness` 才显示门禁。mock 成功不代表真实模型质量或生产就绪。

前端修改要部署到后端静态服务时，先 build，再按 `npm run server:web:sync` 同步；先检查脚本目标，确认不会覆盖需要保留的产物。

## 四、旧电脑路径与外部依赖

- `scripts/build-android.mjs` 默认 JAVA_HOME 和 ANDROID_HOME 含旧机路径，用环境变量覆盖。缓存默认是项目盘根 `CodexBuildCaches`；若目录不可写，设置上述专用变量。
- `server/scripts/deploy-cloudbase-stage.mjs` 把 CLI 路径写死到 `%APPDATA%/kimi-desktop/daimon-share/daimon/npm-global/node_modules/@wxcloud/cli/bin/run`，新电脑不应假设存在。读脚本后改为新安装位置或可配置入口，验证 CLI 版本/登录/目标环境；不要为了查路径直接执行部署。
- 本机 `android/local.properties` 未发现，别依赖迁移它来定位 SDK；使用环境变量或在新机生成本地配置。
- 本机有 `C:/Users/REDACTED_USER/.android/debug.keystore`，它不在 ZIP。要保持测试 APK 可覆盖安装、避免卸载导致设备身份丢失，需要安全迁移同一 debug keystore 或使用确定相同的测试签名。正式公司 keystore 另由公司保管，本次未确认其存在/位置。
- 自定义 Codex skills 在旧机 `C:/Users/REDACTED_USER/.codex/skills`，不在项目包，也不是应用运行依赖。需要时单独迁移自定义技能，检查其引用路径；不要把整个用户配置/登录文件当普通源码提交。
- 云控制台/CLI、商户平台、AppID 管理权限、OSS/RAM 权限需在新机重新确认。浏览器登录态和旧终端进程不在交付范围。

## 六、不要踩的坑

- 不要在迁移过程中执行 git clean/reset、批量移动/删旧材料，或无差别提交全部输出。现有未跟踪目录中既有必要源码，也可能有敏感日志/证据。
- 不要直接运行旧供应商比较/生图脚本、`_百炼免费额度消耗.mjs` 等历史脚本：可能产生真实调用费用。
- 不要直接执行 `deploy:cloudbase:stage` 或 ECS 部署脚本来“验证能否运行”；它们会改远程服务，须先检查配置、部署差异、备份与排空。
- 当前 JSON/OSS 快照闭测方案只允许一个写实例；SQLite 是单主机方案，也不能放 OSS/NFS 或跨机共享。
- `merchant_test` 会真实扣款；`live` 不能只改开关开启。不能用风险勾选替代已购权益恢复。
- 供应商 `ERASURE_PARTIAL` 未解决不能写“全部删除”；AI 标识、备案与材料模板也不能冒充实际通过证据。
