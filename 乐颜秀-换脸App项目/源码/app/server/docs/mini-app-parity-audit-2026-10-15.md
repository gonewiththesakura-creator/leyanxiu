> 阅读顺序：下文是本轮修复前的原始静态对照，保留其问题和行号作为追踪依据。后续本地修复、独立审查和官方 IDE 布局验收见 `mini-product-correction-2026-10-15.md`。不能继续把下文所有“当前行为”当作修复后状态，也不能把修复前缺口从记录中抹掉。

日期：2026-10-15。范围：当前工作区源码的静态对照；未操作云、IDE、浏览器，未执行支付、上传、生成或部署。本清单不证明任何端上运行效果或当前线上可用性。历史交接快照、Git HEAD、离线测试与真实运行验收不可互相替代。

## 结论与纠正边界

当前小程序保留了原版的 17 个图片效果数据，但制作链路尚未达到原版交互和视觉标准。最明显的缺口是：卡片前置额外“核验”步骤；选图页由白灰蓝主操作变成黑粉长表单；相机入口缺失；没有独立制作进度与结果页；零余额仅禁用制作按钮，缺少对应位置的次数不足购买引导。

原版没有独立的 `Upload.tsx` 或 `Paywall.tsx`。选图、制作进度、结果均在 `src/views/Flow.tsx`；套餐页在 `src/views/Purchase.tsx`。原版的次数不足处理是页内提示与“查看套餐”按钮，并非余额不足弹窗。原版年龄选择只有 20 / 40 / 60 / 80 四个按钮，没有滑块。

视觉与导航恢复不能扩大业务范围。当前小程序严格绑定的 `natural-avatar`、`modern-comic`、`gentle-watercolor` 三个效果仍须服务端快照唯一匹配、全局可用、单项 included 与 available 均为 true。其余 14 项只保留目录与预览，视频保持关闭。不得把原 App 较粗的能力级放行方式移植回来，也不得将漫画、水彩描述成保真或覆盖所有人群。

## 3. 最小恢复顺序

1. 补足零余额的可见原因、查看套餐入口与服务端不足错误分支；保证取消不会产生订单，购买不会由错误重试自动发起。
2. 让所选目录卡片到专用选图页的路径连续，减少额外核验门槛，但保留原生隐私、服务端唯一匹配、included 与 available 校验。
3. 按原版恢复选图 / 制作中 / 结果三阶段的页面层级、白灰蓝制作视觉、图片比例及主操作位置；目录维持原黑粉视觉，套餐维持其独立购买风格，不把全 App 误认作统一白底。
4. 补相机入口；如增加大图兼容，先本地归一化后满足现有传输限额，再进入独立授权与上传流程。
5. 完成结果保存、再制作、完成返回及可支持的分享；用真实任务阶段替代原版随机进度。最后逐页核对文字尺寸、点击热区和原图水印。

## 4. 后续端上验收清单（本次未执行）

- 匿名浏览：四分类、17 项、类别切换、图片和标题均正确；浏览目录不应被描述为已经授权上传或制作。
- 三项精确导航：分别点击自然 AI 头像、现代漫画像、温润水彩像，进入相同 ID 的上传页；换效果后不串 ID，不以其他效果 fallback；服务端重复 ID、缺失 ID、未知 ID、included=false、available=false 均关闭。
- 其余目录：14 个关闭项与视频仍可按既定预览规则展示，关闭说明清楚，不发起真实生成。
- 选图：相册取消、相机拒绝、文件不支持、过大、损坏均有可理解反馈；本地预览不自动上传；更换照片后主体与人脸授权重置。
- 零余额：按钮附近有“次数不足”与可操作的套餐入口；进入套餐、取消、返回都不自动下单、上传、生成。刷新后余额恢复应正确更新。
- 授权：供应商、用途、协议和当前事实一致；本人 / 授权主体与单独人脸授权必须主动选择；拒绝、隐藏页面、退出与切换账号后不沿用旧账号照片、余额和授权。
- 任务：一次点击创建至多一个持久任务；超时、冷启动、断网或未确认只恢复同一任务查询；制作中不能二次提交；页面明确展示真实阶段，不伪造完成百分比。
- 结果：保留完整 AI 水印；保存使用实际允许的下载与相册能力；再制作、个人作品、完成和返回不会错误重放生成；删除需保留既有确认与服务端保护。
