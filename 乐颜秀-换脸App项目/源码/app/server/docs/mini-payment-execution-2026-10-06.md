日期：2026-10-06，北京时间。仅微信小程序主线；本文件不把本地测试当云端部署、真实支付或平台审核通过。

## 决策与依据

保留已有微信小程序、微信虚拟支付、微信云托管和 SQL 账本。先复用内置 MySQL 的同环境内网完成沙箱闭环，不因额外 TLS 设计立即购买独立数据库、NAT、互联包或迁移云函数。

用户提供的工单 202609301555 显示：腾讯工程师 9-30 21:15:51 确认内置 MySQL 不支持 SSL；21:22:23 说明独立 TDSQL-C 可管理 SSL，但会增加实例费用和网络接入步骤，适合 TLS 强制要求场景。中间“保留 TLS”是此前工单追问中的项目方案，并不是微信平台规定，也不是本轮用户单独新增的约束。

[微信 MySQL 文档](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/guide/mysql/)明确同环境服务与内置库可内网访问，并不建议开放数据库外网。[微信官方模板](https://github.com/WeixinCloud/wxcloudrun-express/blob/main/db.js)提供普通 MySQL 接法。本轮核实的[小程序网络要求](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html)针对客户端与服务器 HTTPS/WSS，不能据此推导数据库必须 TLS。没有查到统一数据库 TLS 条款不等于完成本业务合规认证。

私网并不加密 SQL，也不提供 TLS 的服务端身份与传输完整性保障。限定环境、账号和 IP 只是减少误配置；应用层 session_key 加密不能保护全部查询。代码中的私网选项本轮仅用于沙箱，真实收费装配仍关闭。正式运营的数据库风险评估应依据实际网络访问者、数据、备份及适用要求完成；只有确需 TLS 时再评估独立数据库成本，不把采购预设成唯一答案。
