## 本轮实现与交叉审查

- `photo-jobs/application.js`：显式同库装配，只接受已审批的服务端效果定义。上传与生成清理均为就绪必要项；停机等待已准入 HTTP、迟到上传及生成。拦截实际旧入口，避免旧同步生成、上传或账户删除绕过新流程。未修改大型旧 `index.js` 或支付测试包。
- `generation-repository.js`、`generation-pipeline.js`：固定一次生成、一次结果 PUT、一次输出审核的持久意图。未知结果不自动重发；已知成品允许保留原 claim 恢复，重新核对所有者、同意、效果及真实账本权益，再发布和消费一次。
- `generation-cleanup.js`：同库删除责任、精确对象键、删除前持久记录、DELETE/HEAD 回执及后续复查。单次对象缺失仅为当前观察，不把迟到 PUT、旧版本或备份排除在外。
- `qwen-provider.js`：当前固定国内编辑模型 `qwen-image-2.0-2026-03-03`，每次仅一图，固定服务器参数；输入走实际校验字节，不创建源照片公网链接。旧 `qwen-image-edit-plus-2025-12-15` 的目录可见性已变化，旧回执与策略不能冒充新型号。官方 FAQ 明确结果使用动态 DashScope OSS 域名，本轮修复此前仅允许两个文档示例主机的兼容缺陷。只从固定 TLS API 的回执接受规定结构，再把实际 hostname 作为单个精确下载目标；保留公网 DNS 固定、TLS 主机名/证书、无重定向/重试和体积时限。域名语法不证明桶归属，不能作为任意用户 URL 下载接口。
- `media-ports.js`：同意和输入资产在读取前后复查；将真实存储字节合同接入生成链。交叉审查发现并修正了输出对象前缀及 `expected` 参数不一致。
- `image-marker.js` 与 `mark-ai.py --stdio`：复用实际 Pillow 编码及 XMP 写入，经管道处理，避免临时图片文件。PNG 在完整容器校验后再解码，拒绝损坏 CRC/APNG；子进程不继承供应商密钥，执行及输出均有上限。`verified` 仅表示写入后自检通过，不表示符合性认证。
- `candidate-host.js`：在同一数据库上复用真实持久微信身份、原支付服务和图片应用；购买固定关闭。外层独立阻止关闭时的新上传/任务 POST，保留原键、旧记录查询、撤回与清理；图片请求不经过支付的 128 KiB body reader。排空等待已入场的身份/支付/图片操作和健康检查，不提前关闭数据库。
- `generation-lifecycle.js`：组合现有单次意图、生成、标识、审核、存储与清理端口。真实检查报告必须同时匹配模型、策略与版本，并确认输出和两份审核临时对象的缺失观察；包装字段不能伪补旧报告。标识或验收缺失关闭生成，但不停止已有清理责任。
- `candidate-server.js`：显式启动同库候选服务，默认关闭购买及全部工作器，输入采用 baselineCheck、输出采用 aigcCheck。只读检查真实 Python/Pillow/中文字体及经哈希固定的验收文件；拒绝泄露请求信息的调试环境变量。收到停机信号后先排空业务及底层 SDK 操作，最后关闭数据库。
- `candidate-public.js`：补齐实际创作页刷新所需的两个公开 GET，避免任一 404 使整页失败；对匿名及不同账户返回相同资料，复用既有供应商、保留期、协议网址配置，仅投影当前模型明确公开字段。缺失资料仍待完善，能力保持不可用，不公开内部评估引用。报告接口在身份校验后明确返回未受理，不保存正文或伪造 ticket；客户端保留旧有效回执、旧未知申请及其他账号/支付状态。公开文档禁止签名查询参数和非规范地址。
