# 微信小程序支付正式接入路线与执行状态

> 2026-10-06 路线修订：下文保留 10-04 历史判断。独立 TLS 数据库不再是继续联调的必经步骤；现有内置 MySQL 同环境私网沙箱接入已完成本地受限实现。正式收费仍须实际验收，未变更线上安全配置。以 `mini-payment-execution-2026-10-06.md` 的后续执行顺序为准。

日期：2026-10-04。范围为已有小程序支付系统的接入决策、代码修复和云资源只读盘点。本文件不是上线批准，也不是新增资源采购申请。

## 决策

保留微信原生小程序、微信虚拟支付、微信云托管和已有 MySQL 账本。云托管支付服务通过服务级 VPC 连接同地域支持 TLS 的 MySQL，校验证书链和连接主机名，数据库维持私网。优先复用已有合适实例；确需新建时先列出规格、备份、最低常驻费用和可用性方案，再确认采购。

服务级 VPC 是微信官方支持的网络能力，不需要先购买旧的资源互联包。此方向无需迁移成云开发文档数据库、重写支付账本或离开微信小程序客户端。TLS 是本项目工程安全策略，不是已经证明的微信统一上线强制条款。

保留现有 `leyanxiu_xpay_sandbox` 作为已验证迁移的历史沙箱库；正式 env=0 使用单独逻辑库和账号，不能把绑定 env=1 的账本直接切成 env=0。逻辑库隔离不等于必须购买两套实例。

9-30 的 DMC 实查已证明旧沙箱 12 表、8 索引、6 个强制 CHECK、schema v1；同日实例 have_ssl=DISABLED，腾讯云支持明确答复内置形态不能启用 SSL。当前不能对该实例直接套用普通 TDSQL-C 的开启 SSL 操作。新增 `vp_auth_sessions` 第 13 表还没有真实迁移。

CLI 验证只覆盖上述微信托管环境，尚不能证明腾讯云账号下没有其他可复用实例。已有浏览器控制本轮失败：插件报 `unsupported Codex auth method: apikey`；桌面控制因不能可靠识别 Chrome 当前 URL 而安全停止，未继续尝试绕过。无法由此完成腾讯云其他数据库、工单最新回复、实际备份/回档配置的核实。

本日继续执行修正：官方 SDK 1.1.4 在 IDE 适配下把可选 `region` 原样放入请求体，而 CLI envelope 已设置上海地域；部分接口因此报 `UnknownParameter`。`scripts/check-mini-cloud-access.mjs --network` 已移除重复字段、补足安全错误码提取，真实只读复验成功。暂停实例返回空账号列表现明确标记 `accountsEnumerationConfirmed=false`，不再产生空账号已确认的歧义。此改动不是云资源变更，也没有连接业务数据库。

用户明确要求保留 API Key 登录。`codex login status` 的脱敏检查确认当前方式为 API Key；不再建议切换登录、不修改认证文件。官方文档支持 API Key 本地工作，但部分插件连接能力受限；当前浏览器接口报错是本机实测，不能推广为所有版本均不支持。后续如尝试恢复桌面路径，应由用户将现有 Chrome 切到明确云控制台页面并显示完整地址，再由工具重新验证 URL；不能保证这个动作一定修复读取，不能换自制控制接口绕过安全检查。

## 按依赖执行，不并行改动正式资源

1. **确定可用库和网络。** 在已登录控制台核实同地域已有支持 TLS 的实例、归属账号、VPC/子网、备份及可用区；没有合适资源再取得具体费用。当前此项未完成。用户不需要把账号密钥发到聊天。
2. **连接与账号。** 为独立支付服务配置服务级 VPC/子网，预留弹性网卡 IP；运行账号仅对应逻辑库 CRUD，迁移账号单独管理。轮换曾出现在旧截图里的沙箱密码。配置匹配主机名的 CA，验证实际连接 `Ssl_cipher` 非空及 TLS 版本；不把配置文件写了 CA 当作链路已加密。
3. **数据库与恢复。** 先备份，再按目标库现状执行原 12 表迁移和认证表增量；启动不自动 DDL。真实 MySQL 验证重复通知、并发权益扣减、死锁、提交结果未知时恢复。全部 vp_ 表、身份映射与加密密钥纳入一致恢复；隔离恢复演练后撤销旧会话，验证原用户权益和出站任务。
4. **沙箱部署和微信验收。** 部署 r3 候选到隔离服务，初始 closed/XPAY_ENV=1。云端健康、认证、账本与回调核验通过后才填写小程序服务名和切换业务推送，再进行真实微信沙箱支付/取消/重复通知/退款/换设备。r3 的本地 HTTP smoke 不替代这些验收。
5. **正式付费入口。** r3 明确拒绝 env=0，不能仅改环境变量升级为正式收费。先补受控 merchant_test 装配、服务器端测试账号/商品/单笔及累计金额/期限限制；真实金额上限与账号明确后才使用正式渠道。生产持久身份、管理员 MFA/审批、恢复、退款异常及财务核销必须逐项有证据。
6. **完整产品发布。** 当前原生小程序主要是支付验收页面。接通审核过的图片效果/短视频模板与既有权益预占、成功扣减、失败返还逻辑，核对素材授权、隐私同意、结果标识和项目原有资质门槛；实际商品/成本/退款文本与 Android/iOS 平台验收完成后再提审收费版本。月费无限制与永久 AI 算力未上架；示例 photo10 仍不是已确认正式定价。

第 2 步服务网络配置按官方文档会创建新版本，因此必须在配置可复核、回退版本明确后执行；不能把它当只读查看。正式可用性需实查实例规格/备份恢复；内置 MySQL 文档写单可用区，不能以页面“运行正常”当高可用证据。旧文档“未集成备份”与当前界面“备份与回档”应以实际配置复核，未据此断言没有备份功能。
