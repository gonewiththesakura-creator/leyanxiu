启动文件是 `photo-jobs/production-server.js`。它只接受 env=0 与独立正式库/账号，并在运行时核查数据库身份；`XPAY_ENABLED=true` 仅装配接口，`XPAY_MODE=closed` 仍关闭购买。所有图片生成、处理、清理与支付对账开关均为 `false`。清理关闭仅适用于尚未接受真实用户媒体的闭售装配阶段，接收上传之前须配置真实保留期并启用清理。

## 先补齐闭售启动确实需要的配置

1. 使用已建的正式库及专用账号 `lyx_xpay_prod`@`%`，数据库名固定 `leyanxiu_xpay_production`；不得继承沙箱账号。该账号最终权限仅 USAGE 与准确限定正式库的 SELECT/INSERT/UPDATE/DELETE，见 [云端初始化验收](../mini-production-database-2026-10-11.md)。密码保存在已限制 ACL、被忽略的 `.env.mini-production-db`，由安全装配只读取需要的字段，勿覆盖该文件或 `.env.mini-production`。精确内网主机、环境和实例由 `payments/virtual/mysql-transport.js` 固定目标核对，不开放公网，不给应用建表/授权权限；实际账号登录、CURRENT_USER 与库绑定仍需只读验证。
2. 安全注入原小程序 AppSecret、正式 AppKey、OfferId、会话加密密钥、消息配置，以及已用的阿里云服务端凭据、私有 OSS 参数和大陆北京工作空间端点。2026-10-12 主线已在微信后台比对正式 AppKey，确认与受保护的 `.env.mini-production` 一致且非沙箱 Key；尚未据此完成正式支付验收。不要把任何值发到文档、聊天或构建包，也不要整份加载沙箱环境文件。`DASHSCOPE_BASE` 留空会被拒绝，须沿用已验证的精确配置。
3. 使用本目录的 `closed-policy-2026-10-12.json` 及其实际审阅记录。原图/结果期限均 24 小时，全局/每人上传限额 20/5，清理参数已确定；`approved`、`reviewReference` 只表示内部配置审阅，不代表政府、微信或法律批准。`approvedEffects:[]` 保持为空，所有运行开关保持 false；正式文案、效果与外部资料尚未完成，不开放生成。
4. 按同名 `.sha256` 核对策略原始字节，再配置 `PHOTO_PRODUCTION_CONFIG_FILE/SHA256`。文件需为普通文件、不得使用符号链接、大小不超过 64 KiB；拟挂载 `/run/leyanxiu-config/photo-policy.json`，由非 root 运行用户只读。复制或换行变更后应复核实际摘要，不能使用旧 pending 模板摘要。
5. 原样只读挂载 `server/evidence/mini-photo-synthetic-generation-v4.json`，按清单填写图片证据文件和摘要。不要修改原始报告、重放其调用日志或把它填进 `XPAY_ACCEPTANCE_FILE`。可缺少图片证据而保持能力关闭，但不能以失败/缺失证据开放生成。

内置 MySQL 的私网例外仅用于已固定的同环境、同实例、专用库/账号；不得通过设置 `NODE_TLS_REJECT_UNAUTHORIZED=0` 关闭其他服务的 TLS 校验。调试输出变量保持空。Docker 内的 Python/字体、证书挂载及非 root 文件可读性仍需真实 Linux 构建/运行验收；Windows 的合成测试不能替代它。
