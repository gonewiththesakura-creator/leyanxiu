## 结论与执行顺序

首发只承诺一个已经实测可交付的图片效果和对应次数商品。复用微信小程序、虚拟支付、云托管、现有数据库与账本，无需先迁移技术栈。按以下依赖推进：

1. **图片闭环**：同一个微信用户选择照片、分别同意必要处理、提交任务、成功交付标识图片、消耗一次权益；确定失败返还，结果未知查询原任务，保存、删除、撤回可用。不能把支付账本测试当作图片服务已开放。
2. **正式交易闭环**：确认已签约的虚拟支付主体和正式商品；使用独立的 env=0 装配与账本隔离完成受控真实购买、交付、查单和退款。env=1 服务不能只改环境变量变成正式收款服务；沙箱也不能宣称不涉及真实资金。
3. **资料与实际服务对齐**：核实已有认证、备案、服务类目、虚拟支付及 AI 相关登记状态；补齐真实运营者、供应商、隐私、投诉和服务规则。已有合格资料直接复用，不重复注册。
4. **微信审核和发布**：用与提交版本对应的隐私指引、实际类目、可完整使用的首发功能及验收记录提审；获批后发布。代码通过测试、云服务健康、沙箱交易成功均不等于审核通过或正式发布。

第 1 项代码工作与第 3 项已有资料核查可以并行。不得为减少步骤而将未实现能力标记为已验收。

## 可以直接由代码完成的工作

- 由图片主线接通**同一用户、同一本权益账本**的首发效果，验收幂等创建、结果未知恢复、一次扣减、确定失败返还、私有素材授权及结果保存。仅对真实上线的效果开放入口。
- 接入能对真实输入、输出图片作判断的审核流程，并保留拒绝、超时、人工处理和投诉记录。现有关键词函数不能替代图片审核；具体采用技术或人工方式，要能实际承担服务量和风险，不要求为了过门禁购买指定供应商。
- 补原生端能到达的客服/投诉、协议、第三方说明、注销入口；复用已有服务端路由。注销应说明依法保留的交易记录，并准确显示供应商删除待完成状态，不能承诺立即删除所有数据。
- 将真实选定的身份认证方式接入逐用户记录；浏览和非必要步骤不额外收集身份证。是否触及未实名用户的信息发布限制，按实际功能判定；不要把微信登录成功直接标为实名完成。
- 对**实际保存到相册的最终文件**验收可见和文件元数据标识、内容标识符；将标识方式说明放入服务协议。若首发仅图片，门禁应与图片能力匹配。
- 收窄内部 readiness 的无关范围：`publicComplianceConfig` 目前要求视频换脸及五类图片共六项披露；`ai-marking` 还包含视频工具检查。图片单功能首发不应被未开放的视频能力阻断，更不能伪填供应商资料过关。

上述项目中持久任务、原生异步流程、服务入口、图片标识和内容审核适配器已有本地实现；未完成的真实媒体装配、资料、部署和现场验收保持未完成状态。

2. **一项首发服务的真实约定**：具体效果、次数、价格、有效期、失败处理、退款规则及客服渠道。测试 `photo10` 的名称和价格不是自动获批的正式商品合同。

4. **必要的评估与说明**：敏感个人信息处理的影响评估、面向人脸编辑能力的安全评估及对应记录；可以依据实际服务自行组织，不等于必须采购外部认证。项目的 `PIPIA_REFERENCE` 是证据索引，不是行政许可。

## 官方要求与项目内部设计的边界

**虚拟支付。** 微信将付费功能等虚拟商品纳入小程序虚拟支付；不可改用个人收款码、H5 或外部 App 绕行。当前接入文档适用于已认证的企业、个体户等受支持主体；道具开发版与发布版分开。发货须通过通知或主动查单可靠确认，客户端成功回调不能独自证明交付。退款发起成功不等于退款完成，仍需查询最终状态。[微信虚拟支付接入](https://developers.weixin.qq.com/miniprogram/dev/platform-capabilities/business-capabilities/virtual-payment.html)、[运营规范 5.13](https://developers.weixin.qq.com/miniprogram/product/index.html)

**iOS。** 当前官方文档列明 iOS 使用 Apple IAP、微信最低版本要求、只支持 env=0，不支持沙箱；退款入口与其他端不同。Android env=1 验收不覆盖 iOS。首发支持哪些端要明确；未支持端应准确关闭购买，不能将所有平台的成功记录伪造为一项“已验收”。[同一官方接入文档的 iOS 说明](https://developers.weixin.qq.com/miniprogram/dev/platform-capabilities/business-capabilities/virtual-payment.html)

**备案和类目。** 小程序需完成适用的备案，所选类目须与实际服务一致。微信提供备案入口和具体材料清单，特殊行业另有对应审批；不能仅凭“收费图片”推定必须办理某一种经营许可证，也不能把 Android APK 签名材料搬来。当前账号的备案和 AI 换脸类目已实查通过，最终实际首发能力仍须与提交资料相符。[微信备案操作指引](https://developers.weixin.qq.com/miniprogram/product/record/guidelines)、[运营规范 5.7](https://developers.weixin.qq.com/miniprogram/product/index.html)、[工信部 APP 备案通知](https://www.gov.cn/zhengce/zhengceku/202308/content_6897341.htm)

**隐私声明。** 在后台声明实际收集和处理的信息，并在相关隐私接口调用前同步用户同意；开发版本提审时的隐私指引与现网版本的维护位置有区别。现有 `__usePrivacyCheck__` 配置不是绕过后台声明的开关。只声明和请求实际需要的选图、相册保存等能力；尚未采用手机号认证时不要提前索要手机号。[用户隐私保护指引](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/)、[隐私授权开发指南](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/PrivacyAuthorize.html)

**网络配置。** `callContainer`/`connectContainer` 云托管调用无需另配通信域名；现有代码保存结果使用 `wx.downloadFile`，实际对象下载主机仍需按服务器域名规则核查。无需仅为云调用再买一个 API 域名；也不能据此推断任意图片下载域名自动可用。[微信网络说明](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html)

**人脸与内容安全。** 深度合成规定要求输入和输出审核、投诉入口及人脸编辑相关的单独同意；可采用技术或人工审核。实名条款中明确限制向未认证用户提供信息发布服务，不能将其简化成所有浏览均需上传身份证。人脸编辑模型/模板需依规定自行或委托评估，具体服务是否涉及备案、安全评估等条件，应按真实能力核对。[深度合成规定第 9、10、12、14、15、19、20 条](https://www.cac.gov.cn/2022-12/11/c_1672221949354811.htm)

**个人信息。** 涉及生物识别等敏感信息时，需特定目的、充分必要性、严格保护及单独同意，并履行额外告知；敏感信息处理、委托处理等情形应事前进行影响评估并留存记录。若服务未成年人，还应按实际年龄范围落实相应规则，不能把“本人勾选”当作监护人同意。[个人信息保护法第 28—31、55—56 条，官方全文](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/bgt/art/2023/art_f374e8245320413181742e6d1baf4366.html)

**AI 标识。** 图片显式标识应在文件中可见；下载、复制、导出的内容应带标识，并按规定添加包含生成属性、服务提供者和内容编号的文件元数据，协议说明标识方式。平台页面文字不能代替导出成品标识；须以实际文件和适用强制标准验收。[AI 生成合成内容标识办法第 4、5、8、11 条](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)

**AI 备案/登记。** 最新公开公告区分已备案服务和通过 API 调用已备案模型的应用/功能，后者由地方网信部门按要求登记；上线应用应展示使用的模型名称及相应备案或登记信息。应根据实际供应商、能力和主体所在地核实路径，不泛化为每个图片应用都要重新做基础大模型备案。[国家网信办 2026 年 7—8 月备案信息公告](https://www.cac.gov.cn/2026-09/14/c_1791136833136332.htm)

项目使用独立逻辑库、严格 TLS 策略、固定格式验收文件、30 天证据有效期、视频工具探测、所有端同时验收等，是具体实现或内部风控决定。它们不能冒充微信对所有小程序的统一上线条款；调整时仍须保持交易隔离、真实交付、数据保护和可恢复性，不能删除必要安全控制来制造“ready”。
