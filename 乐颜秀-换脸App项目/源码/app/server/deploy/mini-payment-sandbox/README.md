# 小程序支付独立沙箱服务

只复用 Hono、MySQL、既有虚拟支付账本和微信适配，不启动旧 App 服务，不导入其媒体、身份快照、供应商配置或密钥。入口只接受 `XPAY_ENV=1`，`XPAY_MODE=closed/sandbox`；拒绝 `env=0` 正式通道配置及 SQLite 部署。这些限制不能保证不发生真实扣款。

2026-10-08 资金语义修正：撤回“沙箱不扣真实资金”的保证。已核对官方合同未支持这种推论；沙箱联调可能实际扣款，以微信收银台及支付记录为准，图片创作尚未开放。每次可能拉起支付前必须明确该笔金额并由用户确认；取消不能调用购买，也不能清除原有待确认订单。不得为了省事切换 `env=0`。原路退款结果以渠道确认为准，不把退款接口受理当到账。

2026-10-08 实际验收：agent在Android真机明确执行一次 `requestVirtualPayment`，用户报告余额不足。查原单最初为 `XPAY_HTTP_UNCONFIRMED`；云调用已开启但路径白名单为空，补充 `/cgi-bin/stable_token` 与 `/xpay/query_order` 后，原单渠道状态6、本地closed、标价990分、权益0。最终另有一笔触发来源未确认的同价订单，两笔均closed、权益及退款均0；本轮没有成功支付或退款验收。固定010→011修复已发布并核验100%流量，只关闭新购，保留查单和对账。真实私有入口下单负测503且订单数不变，公网保持403；资金提示的新客户端UI仅在模拟器检查。完整证据及后续状态以执行总记录为准。已构建r9内README是发布前快照，不回写不可变候选包。

新增 `vp_auth_sessions` 与原有 `vp_accounts` 同库保存认证会话。先备份，再由管理员执行包内的增量 SQL，核验约束和运行账户 CRUD 权限；启动程序只检查，不建表。用户的微信身份取自服务端 code exchange，已有账本 userId 原样复用。旧 compliance 身份的迁移需要单独核对，不能根据用户名自动合并。

`XPAY_ENABLED=true` 是初始化账本/API 的必要条件，并不代表可以购买。`XPAY_MODE=closed` 允许登录、查单和恢复，禁止创建订单。沙箱新购必须有合法测试目录、非空 `XPAY_TEST_USER_IDS` 和 `XPAY_RECONCILE_ENABLED=true`；运行时按已认证的内部账号校验白名单。该服务只验沙箱权益账本，不要求伪造真实图片用途已审核的声明；health/products 显式标记 `ledgerOnlySandbox=true`，图片生成仍未开放。本机私有配置仍 disabled/closed，受控部署在内存中生成云端白名单环境。

运行环境需提供 AppSecret、沙箱 AppKey、OfferId、回调配置、账本 session_key 加密密钥及 MySQL 配置。构建包不含这些值。入口不读取默认 `.env`；不得把整份旧 App 环境变量导入。默认 MySQL TLS、CA 与主机名验证策略保留，无自动明文降级。

2026-10-06 新增显式 `XPAY_MYSQL_TRANSPORT=cloudrun_builtin_private`，仅此隔离沙箱入口可以启用；普通主服务和迁移脚本不接受该选项。它仅允许既有 AppID/环境/实例/REDACTED_PRIVATE_NETWORK_ADDRESS:3306/leyanxiu_xpay_sandbox/lyx_xpay_sandbox 组合，且 env=1、closed/sandbox。必须设置与固定目标一致的 `XPAY_CLOUD_ENV_ID` 和 `XPAY_MYSQL_INSTANCE_ID`，CA 留空以免混淆。这是未加密的同环境内网连接，不是 TLS 的替代加密方案；环境变量仅防误配置，不能证明网络隔离。

使用该路线时，每次部署前执行 `scripts/check-mini-private-database.mjs`，核对官方控制面实例、地址、账号及公网关闭；随后在候选云容器里实际连接核验。先取得备份/账号实况，再完成必要的专用沙箱账号配置及认证表增量，不重复已经完成的密码轮换。具体可审 SQL、顺序及已执行事实见 `docs/mini-payment-execution-2026-10-06.md`。启动先只读验证实际数据库、当前数据库账号和已有沙箱环境绑定，不会自动填充绑定或创建表。这份部署说明本身不是云端执行或收款验收证据。

本服务不提供生成 API、管理员登录或生产上线判断，通用后台特权路由全部拒绝访问。开启 `XPAY_RECONCILE_ENABLED=true` 后，每 30 秒处理持久化查单、发货及已批准退款。白名单用户可通过 `/api/mini/payments/sandbox/refunds/:id/confirm` 明确确认本人 env=1 退款；金额和审核身份仅由服务器生成，并留审计。重复确认不创建新退款，渠道终态确认才算成功。停止新购后应保留白名单和对账运行直到已有任务处理完毕。每实例登录限额为每分钟 20 次及同时 8 次；正式多实例入口限流尚待独立验收。

公众平台安全消息回调复用已有逻辑；云托管路径采用渠道主动查询核验，正文与微信来源头均不能证明付款或退款。发货必须主动查单成功；退款必须已有本地批准、金额和渠道退款记录逐项匹配。HTTP ACK 不证明微信已确认发货，保留出站发货任务由调度调用渠道发货 API 后完成。iOS 问询、渠道主动部分退款及其他不支持事件仍非零错误并告警。具体已部署版本和实测结果以 `docs/mini-payment-execution-2026-10-06.md` 的日期记录为准，不用本说明替代运行状态。

一致恢复边界为全部 `vp_` 表和加密密钥。24 小时 bearer 仅存摘要，与 10 分钟微信支付 session_key 分开；认证每次查库，注销立即对另一个服务实例可见。恢复演练后必须撤销恢复前会话，核验同 AppID/openid 返回原 userId 和权益。

本地 SQLite/微信桩测试只能说明代码行为，不替代 MySQL、微信真机、正式商品、退款及财务验收。构建包不是验收报告；已部署版本、后续修复准备及最终部署结果必须分别记录。旧 health 的 `realMoneyAllowed=false` 也不能作为“不扣真实资金”的证明。
