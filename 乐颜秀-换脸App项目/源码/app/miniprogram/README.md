最小图片合同：同一 `apiTransport` 必须提供 `/api/auth/wechat` 身份和 `/api/mini/payments/entitlements` 权益、`/api/catalog` 发布效果、`/api/public/compliance` 说明、`/api/capabilities` 图片能力、`/api/consents` 当前版本及授权记录。客户端在 `POST /api/mini/photo-uploads {image:dataURL}` 前保存上传键与独立生成键；返回持久上传记录，原 ID 或原键查询到 `ready` 后才使用所属 `assetId`。不回退到旧同步 `/api/upload`。`POST /api/mini/photo-jobs {inputAssetId,effectId}` 快速返回持久任务，随后只通过任务 ID 或原幂等键查询；仅成功状态才换取结果链接。作品、链接、删除和撤回分别使用 `/api/works`、`/api/assets/:id/url`、`DELETE /api/assets/:id`、`POST /api/consents/face_processing/withdraw`。不访问需要内部令牌的生产 `/api/readiness`。

客户端要求 `data.miniProgramCreation={available:true,jobProtocol:'photo-jobs-v1',uploadProtocol:'photo-uploads-v1',photoEffectIds:["已复核适用的效果ID"]}`；旧完整后端仍未宣告该异步协议，不能擅自添加字段开启。缺少任一协议、客户端制作开关关闭、图片能力未 `ready/verified`、说明未披露或效果未列入清单时，制作保持关闭。服务端审核的冻结效果与账本用途须一致；客户端不根据剩余次数推断所有效果适用。完整后端已有统一的 `vp_accounts` 身份和 `vp_auth_sessions` 令牌。新增持久创作上下文、上传与生成 HTTP 路由已本地集成验证，但还需与真实审核/私有存储/作品和同意流程共同装配、验收后部署。

选图只在用户点击时请求微信隐私授权，照片先保留在本页内存，不写入长期本地存储；仅本次说明与人物权利都确认后上传。图片限制为 2MB，完整创作服务需要独立的大媒体请求限制，不能沿用支付沙箱的 128KB 消息限制。原生 HTTPS 下载保存还需登记返回对象域名的 downloadFile 白名单并实机验收，拒绝相册权限时不会假报保存成功。
