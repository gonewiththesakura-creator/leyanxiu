# App 统一账号与微信登录：本地实现及上线边界

> 2026-09-30 后续更新：App 目标确认是阿里云 ECS 与 `REDACTED_COMPANY_INFRASTRUCTURE`，独立账号测试 API、公网 HTTPS、免费证书自动续期及模拟器 HTTPS 拒绝路径均已验证，真实短信/微信/付款仍未验收。见 [阿里云实际部署与验收](./App阿里云账号测试环境-2026-09-30.md)。本文的腾讯云检查仅为历史状态；本文 9/29 APK 仍指向历史腾讯云，9/30 阿里云测试包在 `output/app-ecs-https-20260930/`，均不是正式发布包。

日期：2026-09-29。对象：Android 乐颜秀 App；不代表小程序账号、虚拟支付或商户审核状态。

## 最终方案

采用「固定业务 userId + 手机短信登录 + 腾讯官方 Android SDK 微信授权」。订单、套餐、次数和作品继续属于原业务 userId，手机号与微信只是登录方式。

暂不引入 Logto：本次核对发现，其 Android SDK v3 已移除原生微信/支付宝连接器，原生方案需要留在 v2。对当前需要直接拉起微信的 Android App，先复用已有官方微信 SDK 和现有短信模块，避免为了登录再维护一套身份服务与旧版 SDK。此前仅凭“官方连接器存在”推荐 Logto，不足以判断当前版本适配性。

参考：[Logto 官方 Android 快速开始](https://docs.logto.io/quick-starts/android)。今后需要统一多个独立产品的组织、SSO 或复杂权限时再评估完整身份平台。

用户流程：

1. 阅读并同意协议后，选择手机号登录；微信登录仅在 Android 且审核、配置就绪时显示。
2. 微信用户不被强制绑定手机号，可主动添加手机号作为备用登录方式。
3. 登录后购买，套餐写入当前账号；换机/重装后用原登录方式取回同一账号。
4. 两个已经存在的账号不会因“关联微信/手机号”自动合并，更不会搬动余额。
5. “退出 / 切换账号”和“退出所有设备”撤销服务器设备绑定；注销会解除登录身份，重新注册不继承已注销账号的财务记录。

微信首次登录仍可能出现微信授权确认页，不能承诺每次都无确认一步完成。QQ 登录未实现。

## 本次实现

- PostgreSQL 保存登录方式、设备与账号关系、30 天设备恢复有效期、一次性微信 state；登录会话保留已有签名和撤销机制。
- 每次受保护请求核对设备绑定版本，旧签名 token 不能越过退出或账号切换。
- 手机验证码 5 分钟有效、最多 5 次猜测、一次使用；手机号/设备/IP 限流及日短信预算复用现有实现。登录、退出同时作废设备上其他未完成的登录验证。
- 微信 code 只由服务端向固定微信域名兑换，禁止跳转，10 秒超时；不把 AppSecret、access_token、UnionID 返回客户端或写入日志。身份按 AppID + OpenID 区分，不自动使用 UnionID 合并账号。
- 微信关联需最近 5 分钟的手机验证；添加备用手机号需最近 5 分钟的手机号或微信验证。设备自动恢复不会被当成一次新的敏感身份验证。
- Android 增加 `WechatLoginPlugin` 和 `wxapi.WXEntryActivity`，复用腾讯官方 SDK。原有 App 支付回调与小程序 `jscode2session` 路由保持独立。
- “我的”和购买页接入账号组件；登录/退出整页刷新并清除本地套餐额度、支付尝试及待恢复任务引用；异步请求检测账号切换，避免把旧账号响应写回新界面。
- 未登录设备不能创建订单、上传或启动生成。协议链接缺失或短信/微信未配置时，入口保持关闭。
- 注销解除手机号、微信、设备恢复与旧版设备别名；原账本 userId 保留，金额记录不自动删除/转移。短期短信防刷记录失效并清除展示手机号，计数仍保留至现有 24 小时清理窗口，避免注销重注册重置短信预算。
- 生产付款增加统一账号及固定 SHA-256 验收报告门槛，不能只打开一个开关就声称完成真实验收。

## 开启前必须完成的迁移与配置

本轮未修改实际 `.env`、未运行真实业务数据库迁移、未部署线上服务、未提交微信审核。2026-09-29 只读检查：现有 stage 服务仍为旧版封闭测试，匿名模式，正式发布关闭；本机部署配置缺少新账号 PostgreSQL、短信、微信 App 登录/支付及正式协议链接。APK 指向该 stage，不代表新账号服务已上线。

1. 备份账本数据库、身份/会话存储、对象元数据，以及既有密钥的安全备份；用副本演练恢复。不能只备份账本而遗失它所引用的 userId。
2. 盘点历史账号：已有 `billing_phones` 的账号继续使用原 userId；旧设备专属且未绑定手机号的付费账号，必须先核实归属再制定映射，不允许自动迁移成新账号。旧账本订单仍会触发现有人工审查阻断。
3. 在隔离副本执行现有账本初始化/迁移脚本，确认新增 `app_login_*` 表和 OTP 列；实际启用前检查锁表影响、备份和回滚方案。
4. 审核后配置 `RELEASE_CHANNEL=android-app`、`AUTH_MODE=device_key`、`BILLING_BACKEND=postgres`、`APP_LOGIN_ENABLED=true`，以及现有短信配置。`ACCOUNT_OTP_SECRET` 同时影响手机号标识，不能随意更换；轮换需专项迁移。
5. 前端构建配置正式 HTTPS 用户协议和隐私政策链接；更新第三方 SDK 披露，说明微信登录、短信验证用途。测试页里的示例协议网址不能用于发布。
6. 微信开放平台申请的是移动应用登录权限。材料按后台当前要求准备：真实运营主体、App 名称/简介/图标/截图、可审核的应用与登录流程、包名和对应签名信息。包名为 `com.yibohuaxia.leyanxiu`；签名信息必须从实际送审安装包核对，不能使用另一份调试签名替代。
7. 微信审核通过后，服务端配置 `WECHAT_LOGIN_APP_ID`、`WECHAT_LOGIN_APP_SECRET`、`WECHAT_LOGIN_APPROVED=true`；Android 构建的 `WECHAT_APP_ID` 必须匹配。当前原生支付与登录共用该 App 的 SDK AppID，须与商户关联、实际安装包一起核对。AppSecret 只能在服务端。
8. 同一身份库不能随意切换微信 AppID；OpenID 的应用范围会改变。换应用或换主体需先做账号迁移设计。

环境变量名称已加入 `server/.env.example`，实际值不在此文档。

## 真实验收及稳定性边界

正式付费前应完成：真实短信发送/失败、微信拉起/拒绝/未安装/超时/重复回调、签名不匹配、重装换机找回、账号切换隔离、退出所有设备、注销、数据库短暂中断、服务重启和备份恢复。付款还需独立完成真实商户付款、退款、漏回调补偿和账单核对。

账号验收报告使用 `kind=app-account`，真实通过后填写 `result=pass`、`reviewedBy`、`testedAt` 和检查项 `phoneLogin`、`sameAccountAfterReinstall`、`logoutRevocation`、`accountSwitchIsolation`、`legacyAccountsReviewed`、`backupRestore`；配置 `APP_LOGIN_ACCEPTANCE_EVIDENCE` 及文件 SHA-256。不要把本地测试结果写成这些真实验收项已通过。

身份/会话仍依赖现有合规存储；本次没有把整个业务身份存储迁入 PostgreSQL，也没有实现跨存储分布式事务。登录持久化失败会撤销设备恢复，采用拒绝继续的方式保护账号；实际存储持久性、单实例限制和恢复一致性仍须按现有门槛验收。不得因此直接扩为多实例生产运行。

持续管理建议：监控短信成功率/限流、登录失败率、数据库可用性、微信错误率及恢复演练结果；保持 SDK 与运行依赖升级评估。账号合并、人工找回、手机号更换和争议订单处置需要有人工核验流程，本轮没有提供后台一键强制合并。

月度或永久套餐仍使用既有商品与账本设计，本轮不改变售价、期限或无限使用承诺。登录系统也不替代支付、内容处理和正式发布的其他验收。
