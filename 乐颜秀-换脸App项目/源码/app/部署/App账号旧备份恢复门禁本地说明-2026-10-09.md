# App 旧备份恢复检查：本地实现

本轮只新增离线工具与隔离演练，没有读取真实配置或数据库、部署、备份删除、定时任务或短信调用。独立注销 journal **尚未在账号服务启用**，因此不能称为线上已有“防复活”保护；现有历史备份早于 journal 的覆盖起点，工具会拒绝放行。每日一致性备份、异机加密副本、密钥保管与自动轮替仍未完成。

## 现有缺口与本轮范围

`backup-app-account.sh` 会停服务并对 PostgreSQL、SQLite 做同一边界的备份和恢复比对，但没有最新独立注销清单，且脚本仍引用旧 release。`registry.deleteIdentity` 清除手机/外部身份绑定、注销设备、清空验证码校验值；`store.markUserDeleted` 将身份标记为删除并撤销会话。这些状态都属于业务备份，恢复注销前的备份会把它们一并回滚。

新模块不是恢复框架：`account-deletion-journal.mjs` 提供显式配置的独立持久记录；`account-restore-guard.mjs` 直接检查隔离的 PG/PGlite 表与 SQLite 文件；`check-app-account-restore.mjs` 提供只读操作入口。它不恢复数据库、不重放生产注销、不开放服务。

## 可直接运行的本地演练

工作目录为源码 `app/server`，使用与现有 `better-sqlite3` 原生库一致的 Node 22：

```powershell
& 'REDACTED_LOCAL_USER_PATH/AppData/Local/leyanxiu-toolchains/node-v22.23.1-win-x64/node.exe' scripts/check-app-account-restore.mjs --plan
& 'REDACTED_LOCAL_USER_PATH/AppData/Local/leyanxiu-toolchains/node-v22.23.1-win-x64/node.exe' --test --test-concurrency=1 tests/account-restore-guard.test.mjs
```

演练在本次创建的临时目录运行真实 SQLite 和 PGlite：创建账号/套餐/撤回记录/会话/OTP → `PGlite.dumpDataDir()` 与 SQLite backup → 独立 journal 记录注销 → 加载旧备份 → 检查拒绝 → 用现有 registry/store 重放注销，并显式失效其余旧凭据 → 检查通过本项门禁。它检查原套餐仍属于原账号、防刷字段不变、已有撤回不变，已注销身份和旧验证码不可用；不会发送短信。只有 POSIX 权限验证在 Windows 测试注入适配器，真实 Linux 权限拒绝用例在 Windows 跳过，不能据此宣称 Linux 验收已完成。

2026-10-09 本地实测：Node 22.23.1 串行运行该文件，6 项通过、0 项失败、1 项 POSIX 权限测试跳过；三个新工具语法检查及 `--plan` 入口通过。额外覆盖 journal 重开、重复注销幂等、三个真实子进程并发提交、旧清单/过期 checkpoint 拒绝、写入异常固定码、未配置拒绝和未知数据表拒绝。系统默认 Node 24 与当前 SQLite 原生库 ABI 不匹配，所以使用已有 Node 22，未重建共享依赖。

## 实际隔离副本的只读入口

仅支持 Linux/POSIX；不加载 `.env`。操作者须先停止隔离副本所有写入，且不得将它连接到公开业务。`--pg-connection-file` 是操作者显式提供的私有 JSON，唯一字段为 `connectionString`；仅接受本机回环地址和 `lyx_app_restore_*` 数据库名，不接受当前业务库名或 URL 查询参数。示意格式：

```json
{"connectionString":"postgresql://RESTORE_READER@127.0.0.1:5432/lyx_app_restore_drill"}
```

请在受控环境写入实际凭据，不通过聊天或命令行明文传递。PG 会话使用 `default_transaction_read_only=on`，并在 `REPEATABLE READ READ ONLY` 事务内执行 SELECT；SQLite 使用 readonly/fileMustExist。私有输入文件必须由执行者持有且为 0600，直接父目录 0700，路径不可含符号链接或文件硬链接。journal 必须在恢复目录之外；可信 checkpoint 也必须来自恢复目录之外的独立当前来源。

在重放前，建立隔离副本基线（数据库只读，只有明确指定的新基线文件会写入；拒绝覆盖）：

```sh
node scripts/check-app-account-restore.mjs --capture-baseline --identity /srv/lyx-restore/copy/identity.db --restore-root /srv/lyx-restore/copy --pg-connection-file /srv/lyx-restore-private/pg.json --output /srv/lyx-restore-private/baseline.json
```

重放由另行审核的流程执行；本工具不提供 `--apply`。重放后检查，`--backup-at` 使用原一致性备份边界的 Unix 毫秒时间，不能填恢复当天伪造覆盖期：

```sh
node scripts/check-app-account-restore.mjs --check --identity /srv/lyx-restore/copy/identity.db --restore-root /srv/lyx-restore/copy --pg-connection-file /srv/lyx-restore-private/pg.json --journal /srv/lyx-independent-deletions/deletions.db --checkpoint /srv/lyx-restore-private/current-checkpoint.json --baseline /srv/lyx-restore-private/baseline.json --backup-at BACKUP_UNIX_MILLISECONDS
```

只输出固定码、布尔值和计数；失败返回非零退出码。缺 journal/外部 checkpoint、清单摘要/序号不符、checkpoint 超过五分钟、备份早于覆盖起点、未知 PG 表、身份库错误、可用旧凭据或财务/计数改变均拒绝。不得从待恢复的旧 journal 自行导出 checkpoint，再把它称为“可信最新”；工具能比对外部信任锚，不能替代其独立来源与权限管理。操作者应从已停写的权威独立 journal 获取 checkpoint，并通过独立渠道核对，而不是从旧备份取出二者。

## Journal 接口与未来接点

```js
const journal = openAccountDeletionJournal({ file: explicitlyConfiguredPrivateAbsolutePath });
const saved = journal.recordDeletion(authenticatedInternalAccountId);
const checkpoint = journal.checkpoint();
const health = journal.health();
journal.close();
```

导入模块无 I/O，没有默认目录。只有 `usr_UUID` 内部账号 ID、单调序号与服务器生成时间进入事件表；SQLite 同步 FULL 事务提供多进程串行提交，重复注销保持同一条记录。创建文件后同步父目录。写入或底层读取失败用固定错误码拒绝，健康变为失败；不携带手机号、验证码、正文、令牌或原始错误。`readVerified(checkpoint)` 只供私有恢复流程使用，会返回内部账号 ID，禁止将其返回值直接打印。

未来服务接入必须显式开启：完成鉴权、确认账号可注销后，在任何删除副作用前持久记录注销意图。记录失败就拒绝删除，不得成功响应。若随后业务库删除失败，独立意图仍有效，需要重试完成；不能删除该意图来“回滚”。启用前还需明确待完成意图的登录阻断/重试、启动健康、关机 close、systemd 可写路径和独立异机保管。该接点本轮**未接入**，不修改 index/registry/store。

首次创建 journal 只能覆盖此后的备份；不能给历史备份补写一个较早创建时间冒充连续覆盖。该工具没有删除 journal 或清单轮替接口。未来清单保存需覆盖全部仍可恢复的备份，并有独立保管，不能随旧业务状态一起回退。

## 检查覆盖和不能宣称的内容

检查实际 17 张 PG 表。财务基线覆盖账号主键、商户/目录配置、订单、支付事件、套餐发放、预留、退款、账本、审计、对账；SQLite 财务集合一并比较。OTP 防刷基线覆盖 id、手机号派生索引、设备 ID、IP 派生索引、创建时间、猜测次数、发送计数标志和用途。允许清空验证值并消费 OTP，不允许删行或重置计数。

恢复检查要求全部旧会话令牌清空并撤销、设备认证挑战消费、OTP 消费并清验证值、第三方登录挑战消费、账号设备映射清空并到期、旧财务设备别名禁用；重放注销的账号不能保留手机号或外部身份绑定。财务账号与历史套餐保留原 ID，不转移给重注册的新账号。

`RESTORE_DELETION_GATE_PASSED` 仅代表本项离线门禁；结果始终 `reopenAllowed:false`。现有同意/撤回记录与备份基线一致，不代表已同步**备份后**的新撤回；最新撤回独立恢复、两个数据库一致性来源、日志完整性、权限、密钥、网络隔离、外部备份和线上演练仍需另验收。此工具不等于已实现每日备份、异机加密备份或生产恢复自动化。
