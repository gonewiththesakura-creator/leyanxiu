# 乐颜秀小程序 · 交付版审查与开发计划

> 目标：把现有 React 原型整理为可交付的完整测试版；本阶段优先完成前端体验、关键流程、真实服务接入边界与回归验证。

## 当前发现

- 当前前端是手机壳式 React 原型，视觉方向为深色红金，和「苹果风」目标不一致。
- 生成流程在 `generateFusion()` 中对真实 API 失败会**静默回退本地演示图**，交付版容易把真实失败伪装成成功，必须改成明确的演示/真实模式提示。
- 服务端 `/api/upload` 已存在，但前端 API 客户端尚未上传本地照片后再创建真实任务；真实模式目前把 data URL 直接当成 `userPhotoUrl`，不符合供应商公网 URL 要求。
- 作品模型只按图片保存，真实视频结果需要统一保存 `kind`。
- 会员按钮目前明确写了“演示版本不会真的扣钱”，测试版可以保留，但必须标记为演示状态。

## 本轮交付目标

1. 苹果风原创视觉系统：浅色、留白、系统字体、柔和灰阶、蓝色主操作色，避免渐变堆叠。
2. 首页为 Explore/Operate 混合界面：功能入口优先，模板浏览清晰，不使用营销式假数据强化可信度。
3. 完整测试路径：首页 → 选择模板 → 上传/示例照片 → 人脸检查 → 生成中 → 结果 → 保存/分享/作品。
4. 真实/演示模式明确：由 `VITE_API_BASE` 决定，真实 API 失败展示错误，不静默伪造成功；无 API 时才进入演示模式。
5. 真实上传链路：前端 data URL → `/api/upload` → OSS 公网 URL → `/api/fusion`。
6. 构建、启动、健康接口、主要交互全部实际验证。

## 验收标准

- `npm run build` 通过。
- `/health` 返回 ok 且显示 provider/photoProvider/llmProvider/tasks。
- `/api/features` 正确反映照片模板是否可用。
- 演示模式能完整走通，不调用真实云 API。
- 真实模式失败不会伪造成功结果。
- 重点按钮至少 44px 点击区域；手机和桌面预览均不溢出。
