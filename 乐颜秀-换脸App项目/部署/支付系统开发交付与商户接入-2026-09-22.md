# 乐颜秀安卓支付系统开发交付与商户接入

## 当前结论

已实现微信 APP 支付的协议适配、事务账本、安卓 SDK 桥接、购买及退款页面、后台商业管理。当前为本地开发交付，未部署到线上，未进行真实商户扣款，不是已开放的收费版本。

公开收费仍受账号恢复问题阻断：当前身份来自设备密钥，不能确保卸载、清除数据、换机后的权益恢复。不能仅让用户勾选风险提示就宣称解决。需接入可恢复的账号体系（公司确认手机号或微信身份方案），验证账号找回与资产归属后才解除 live 门禁。

商户接入完成前，PAYMENT_MODE 保持 closed_test。merchant_test 专用于真实渠道验收，必须配置明确测试用户白名单；会发生真实扣款，不是模拟支付。不得用普通生产用户联调。

## 已实现范围

1. 服务端按套餐价格快照下单，忽略客户端传入金额和次数；幂等键重复请求不重复创建订单。
2. 微信 API v3 请求签名、响应验签、通知验签和 AES-GCM 解密；核对商户、AppID、APP 类型、订单、金额和 CNY 币种；未知公钥 serial 拒绝。
3. 原生安卓微信收银台调用及回调。原生回调仅通知返回，到账以服务端查单或已验签通知为准。
4. 交易持久化选项 SQLite WAL/FULL，同主机多进程事务防覆盖；原 JSON/OSS 仍用于闭测，不能用于真实收费。
5. 额度发放去重、制作扣减、确认失败返还；拒绝重新使用已返还的制作请求编号。
6. 全额退款申请先冻结额度，所有者审批后发起微信退款；PROCESSING/异常/超时不当成功，保持冻结；SUCCESS 完成，权威 CLOSED 才释放。
7. 停止新销售后，历史订单到账、售后退款可独立处理。
8. 管理后台套餐配置、历史订单、退款审核、支付与退款曲线、额度差异核对、手动渠道补查。收入曲线不包含税费、手续费、模型成本，不是利润。
9. 每分钟补查可通过 PAYMENT_RECONCILE_ENABLED 开启；单轮最多20笔待付款订单、10笔处理中的退款，异常进入现有告警。
10. 正式环境不赠送次数、不使用历史闭测试用余额。试用账本保留，不删除审计记录。

## 部署步骤

1. 生产使用单主机持久磁盘；不将 SQLite 放在 NFS、OSS 或临时容器目录，不跨主机共享同一库。
2. 停止旧实例写入，保留旧账本。执行 `源码/app/server/scripts/compliance-sqlite-migrate.mjs --source <旧JSON绝对路径> --database <新数据库绝对路径> --backup <新备份路径> --report <新报告路径>`。工具拒绝覆盖，核验备份恢复摘要。
3. 设置 COMPLIANCE_BACKEND=sqlite、COMPLIANCE_SQLITE_FILE、COMPLIANCE_SQLITE_VOLUME=single_host_persistent；设置 COMPLIANCE_SQLITE_EVIDENCE_FILE 和工具输出的 COMPLIANCE_SQLITE_EVIDENCE_SHA256。报告最长有效30天，需定期生成新备份证据；另安排异地加密备份。
4. 按 server/.env.example 填写 WECHAT_PAY_*，平台公钥文件格式 `{ "serial": "PEM 公钥" }`。回调地址分别 `/api/payments/wechat/notify` 与 `/api/payments/wechat/refund-notify`，必须为公网 HTTPS。
5. RELEASE_CHANNEL=android-app、PAYMENT_PROVIDER=wechat-app。构建时 WECHAT_APP_ID 与服务端 AppID 必须一致，微信开放平台登记正式包签名；debug 签名不是正式上线签名。
6. 设置 PAYMENT_MODE=merchant_test 及 PAYMENT_TEST_USER_IDS 指定测试账号，用获授权的小额真实订单验收付款、到账、退出重进、取消、退款、查单与商户平台账单一致性。
7. 补完账号恢复、正式签名及整个 App 其他上线门禁后，再讨论公开收费；当前代码不能用人工 verified 标记绕过账号恢复阻断。
