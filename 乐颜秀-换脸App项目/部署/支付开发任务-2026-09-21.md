# 乐颜秀支付开发任务与实施记录

## 已确认的产品规则

正式用户不赠送制作次数，购买后才能生成。允许浏览模板效果。第一期国内安卓微信 APP 支付及次数包，不开自动续费；苹果内购独立适配。公司办理商户及结算手续，技术开发并行。真实渠道验收前不开通真实收费。

## 开发顺序及验收要求

| 顺序 | 交付 | 文件及工作范围 | 验收条件 |
|---|---|---|---|
| P0-1 | 正式收费门禁 | server/compliance-store.js，server/tests/paid-access.test.mjs | 正式环境禁止赠送；历史试用余额不可用于正式制作；独立闭测可保留试用 |
| P0-2 | 交易账本与可靠存储 | 从 compliance-store.js 拆出支付业务；采用事务数据库及唯一索引 | 并发下单、回调重复、进程退出不重复发放；订单金额以服务端价格快照为准；完成迁移与恢复测试 |
| P0-3 | 微信 APP 支付适配 | 新建 server/payments/wechat.js；index.js 注册独立微信回调路由 | 商户签名、微信原始报文验签、通知解密；核对商户、AppID、币种、金额、订单号；拒绝伪造及串单 |
| P0-4 | 安卓购买入口 | src/lib/api.ts、原生支付桥接、购买页及订单页 | 取消支付不发额度；客户端退出仍能到账；以服务端查单结果更新状态；无配置时不可购买 |
| P0-5 | 任务扣减与补偿 | reserveCreation/confirmCreation/refundCreation，任务恢复机制 | 额度冻结、成功结算、确认失败返还；未知状态查单，不盲目退款重试；重复任务不可重复消费或复活 |
| P1-1 | 商业管理后台 | src/admin、管理员 API | 套餐草稿发布、订单查询、退款申请及审批、额度流水；操作审计、权限分离，价格修改不影响旧订单 |
| P1-2 | 对账与风险告警 | 定时账单拉取及后台曲线 | 支付与业务账本差异、付款未到账、退款未完成告警；收入、退款、模型成本分别统计 |
| P1-3 | 商户接入材料 | 部署目录独立材料包 | 固定包名与正式签名、支付页面截图、回调地址、公司操作步骤；资料不包含私钥 |
| P2 | 正式联调与发布 | 真实商户环境、签名安装包 | 真实付款、到账、制作、失败补偿、退款和账单对账全部通过；未通过不得标记支付完成 |

## 第一批执行记录

- 已增加收费门禁回归测试，验证原实现允许正式模式赠送的问题（两条测试先失败）。
- 已修改台账入口：仅非 production 且显式 CLOSED_TEST_MODE=true 时允许发放及使用试用额度。
- 历史试用账本保留供审计，公开模式的可用余额不包含试用，不执行余额清零或删除。
- 该修改仅本地开发，未部署、未启用收款，不代表整个支付系统完成。

## 后续不能省略的边界

现有通用 HMAC 回调不等于微信支付协议，不能直接接正式商户。现有 JSON/OSS 单实例台账不应被当成正式多实例交易数据库。正式支付不得仅凭 PAYMENT_MODE=live 或人工 verified 标记开启。

公司依赖：商户号与 APP 支付权限、开放平台 AppID 绑定、结算账户和签约、套餐定价及退款规则。缺少这些不妨碍前述代码开发，但阻止真实渠道验收。

测试不调用付费模型，不发生真实扣款。正式签名及私钥只存安全配置，不进入 Git、APK、日志或交接文档。
